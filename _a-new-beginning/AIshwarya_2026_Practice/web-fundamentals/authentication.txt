# **AUTHENTICATION (With Clear Examples)**

## **1. SSO (Single Sign-On)**

**Definition:** Log in once → access multiple apps without re-authenticating.
**Why:**

* No repeated logins
* Centralized authentication
* Higher security (credentials stay with IdP only)

### **Common Protocols**

| Protocol             | What It Is     | Used In                                                |
| -------------------- | -------------- | ------------------------------------------------------ |
| **SAML**             | XML-based      | Enterprise apps (HR portals, ERP, internal dashboards) |
| **OAuth 2.0 / OIDC** | Token-based    | Web/mobile apps (Google login)                         |
| **JWT**              | JSON Web Token | Used inside OAuth/OIDC for carrying identity           |

### **SSO Flow (OAuth/OIDC Example)**

1. **User tries to login** to App A
2. App A redirects to **IdP** → Google/Auth0/Okta
3. User authenticates at IdP
4. IdP sends back **JWT token** to App A
5. App A verifies token
6. Same token lets user access App B, App C…

**Real-world example:**
You log into Gmail → you’re automatically logged into YouTube, Drive, Analytics.

# **2. JWT BASICS**

A JWT =
`header.payload.signature`

### Example

**Header**

```json
{ "alg": "HS256", "typ": "JWT" }
```

**Payload**

```json
{
  "sub": "123",
  "name": "Sumit",
  "iat": 1697000000,
  "exp": 1697604800
}
```

**Signature**

```
HMACSHA256(base64(header) + "." + base64(payload), secret)
```

# **3. Password Handling**

* Never store passwords plain.
* Store **bcrypt hashed password**.
* Compare by hashing the user input → matching hashes.

**Example**

```js
bcrypt.compare(inputPassword, storedHash)
```

# **4. JWT Delivery to Browser**

## **Option A: Send in Response Body**

Backend:

```json
{ "token": "eyJhbGc..." }
```

Client:

```js
const token = data.token;
sessionStorage.setItem('jwt', token);
```

**Pros:** Easy
**Cons:** XSS can steal it

---

## **Option B: HTTP-Only Secure Cookie (BEST PRACTICE)**

Backend:

```
Set-Cookie: jwt=eyJhbGc...; HttpOnly; Secure; SameSite=Strict
```

Client:

```js
fetch('/api', { credentials: 'include' });
```

**Pros:** Protected from XSS
**Cons:** Must handle CSRF

# **6. JWT Expiration**

When `exp` hits:

* Return **401 Unauthenticated**
* Either:

  * Force login
  * Or: **use refresh tokens**

# **7. Access vs Refresh Tokens (With Timeline Example)**

### **Assume:**

* Access token → **30 sec**
* Refresh token → **7 days**

### **Timeline**

🟢 **0–30s**
AccessToken1 works for all requests.

🔴 **At 31s**
AccessToken1 expires → API returns **401 token_expired**

🔄 **Silent Refresh**
Frontend sends refresh cookie → gets AccessToken2 → retries request → success.

⏳ **At 7 days**
RefreshToken1 expires → refresh fails → logout → user must login again.

# **8. Practical Real-World Flow (Short + Clear)**

### **Phase 1 (Simple)**

* Only access token
* No refresh
* Token in React Context
* Expire? → logout user

### **Phase 2 (Real Production Flow)**

1. Login → backend returns:

   * `accessToken` in response body
   * `refreshToken` in HttpOnly cookie
2. Access token stored **in memory**
3. Every request → `Authorization: Bearer accessToken`
4. If **401 token_expired**:

   * Call `/auth/refresh`
   * Backend uses refresh cookie → gives new access token
   * Retry request
5. If refresh expired → logout

# **9. Axios Interceptor Example**

```js
api.interceptors.response.use(null, async (error) => {
  const status = error.response?.status;
  const code = error.response?.data?.error;

  if (status === 401 && code === 'token_expired') {
    const refreshed = await refreshAccessToken();
    if (refreshed) return api.request(error.config);
    logoutUser();
  }

  if (status === 403 && code === 'refresh_expired') {
    logoutUser();
  }

  return Promise.reject(error);
});
```

# **10. Cookies (Ultra-Condensed)**

### **What a Cookie Is**

Browser-stored data → auto-sent with every request to the issuing domain.

### Example Cookie

```
Set-Cookie: jwt=abc; Path=/; HttpOnly; Secure; SameSite=Strict; Max-Age=3600
```

### **Secure Attributes**

| Attribute    | Purpose                     | Why It Matters              |
| ------------ | --------------------------- | --------------------------- |
| **HttpOnly** | JS cannot read it           | Prevent token theft via XSS |
| **Secure**   | Only HTTPS                  | Prevent plaintext leaks     |
| **SameSite** | Controls cross-site sending | Protect vs CSRF             |
| **Domain**   | Subdomain control           | Limit which apps get cookie |
| **Path**     | URL path scope              | Limit where cookie is sent  |
| **Max-Age**  | Lifetime                    | Short life reduces risk     |

### **Perfect Auth Cookie Combo**

`HttpOnly + Secure + SameSite=Strict`

# **11. Example Express Authentication Setup**

### **Backend**

(Shortened but complete)

```js
app.post('/login', (req, res) => {
  const token = jwt.sign({ username: 'sumit' }, JWT_SECRET, { expiresIn: '1h' });

  res.cookie('jwt', token, {
    httpOnly: true,
    secure: true,
    sameSite: 'Strict'
  });

  res.json({ message: 'Login successful' });
});

app.get('/profile', (req, res) => {
  try {
    const user = jwt.verify(req.cookies.jwt, JWT_SECRET);
    res.json({ user });
  } catch {
    res.status(401).json({ message: 'Not authenticated' });
  }
});
```

### **Frontend**

```js
fetch("http://localhost:4000/login", {
  method: "POST",
  credentials: "include"
});
```

# **12. HTTP Errors**

* **401 → unauthenticated** (no token / expired token)
* **403 → forbidden** (token valid but access denied)

Examples:

* User not logged in → 401
* User logged in but not admin → 403
